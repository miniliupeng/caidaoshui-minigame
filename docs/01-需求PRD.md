# 彩虹倒水 · 产品需求

版本 0.3.0。竖屏水排序微信小游戏，激励视频变现（IAA）。本文描述当前要交付的可玩范围，不预写未排期的系统。

## 1. 产品一句话

玩家把瓶子里混在一起的颜色水分开，点一次选中来源瓶，再点一次倒进目标瓶。同色倒满，或把瓶子倒空，即过关。卡住时可以看激励视频换一个空杯，或撤销一步。

## 2. 玩法规则

设计容量固定为 **4 层**。颜色用从 0 开始的整数表示，界面上对应 8 套固定配色。

- 只能倒出一瓶最上面连续同色的水。一次倒入的层数 = min(连续顶层数, 目标瓶剩余空位)。
- 目标瓶必须是空的，或者顶层颜色与倒出的颜色相同。满瓶、异色顶层、倒回自己，都是非法操作。
- 空瓶不能被选中。点空瓶只会抖动并提示先选有水的瓶子，瓶子数量和液面都不变。
- 已经选中时，再点同一瓶（严格热区）取消选中。点到空白不取消选中，避免误触丢选择。
- 选中后，可倒入的瓶子用绿色描边标出，热区比普通瓶子更大，并优先命中这些瓶子。
- 一瓶是「完成」当且仅当它是空的，或装满且整瓶同色。全部瓶子完成即过关。
- 没有任何合法倒水且尚未过关，进入卡住页。
- 每关开局赠送 **3 次免费撤销**。用完后，撤销需要看完激励视频。撤销恢复上一步的全部瓶子（含广告空杯带来的瓶子数量变化），步数减 1。历史最多保留 80 步。
- 每关最多通过广告再获得 **2 个空杯**。达到上限后按钮仍在，但只提示已达上限。
- 倒水先播放约 420ms + 每层 90ms 的倾倒，动画结束后才结算胜负。动画期间忽略瓶子点击。
- 倒水结束后液面短晃 **380ms**。晃动只比较统一时钟 `game.now` 与起点的差；差值不在 `[0, 380)` 内（含时钟回绕）就清零，不做常驻闪烁。

第 1 关开局有一次性引导：「先点有水的瓶子，再点目标瓶」。任意有效点击后不再自动弹出，本局进程内记住已关闭。

## 3. 关卡

共 **80** 关，数据在 `src/data/levels.ts`。每一关必须满足：

- 每种出现的颜色恰好 4 层，颜色 id 从 0 连续编号。
- 单瓶不超过 4 层。
- `emptyExtra >= 1`，展开后至少有一个空瓶。
- 开局没有过关，且至少存在一步合法倒水。
- 存在一条解。发布前由 `npm test` 里的广度搜索复验。

难度大致按颜色数上升：前 2 关 2 色 1 空瓶，随后 3～4 色多为 2 个空瓶，中后期 5～8 色、1 个空瓶，瓶子更多但初始状态成组，靠空位腾挪。

通关后把「已解锁关卡下标」写成 `max(当前进度, 本关 + 1)`，只增不减。首页在进度大于 0 时提供「继续」和「从第 1 关开始」。最后一关通关后，主按钮变为「再玩一轮」，从第 1 关再开，进度停在最后一关。

## 4. 页面

| 状态 | 玩家能做什么 |
| --- | --- |
| home | 看标题与主视觉、开始 / 继续、玩法说明、背景音乐开关 |
| play | 点瓶倒水、免费或广告撤销、广告空杯、重开本关、静音 |
| clear | 看步数，下一关或再玩一轮，回首页 |
| stuck | 广告空杯、撤销、重开、回首页 |

状态只允许按玩法切换：开始进入 play；倒水结算进入 clear 或 stuck；广告空杯或撤销成功从 stuck 回到 play；重开仍是 play。

## 5. IAA

三个广告位键，定义在 `src/services/placements.ts`：

| 键 | 场景 | 看完后 |
| --- | --- | --- |
| `empty_bottle` | 对局底栏「+ 空杯」、卡住页「看广告 +1 空杯」 | 增加 1 个空瓶，计入本关上限 |
| `undo` | 免费次数用完后的撤销、卡住页广告撤销 | 撤销一步 |
| `stuck_help` | 预留，与空杯同一类帮助 | 暂未单独使用 |

当前广告位 ID 是占位符 `adunit-...-PLACEHOLDER`。提审前必须在微信流量主后台换成真实 ID。三个场景可以共用一个激励视频广告位，只要键仍然分开，便于埋点。

发奖条件：

- 微信环境只认 `RewardedVideoAd.onClose` 里的 `isEnded === true`。
- 创建失败、加载失败、播放失败、用户中途关闭，一律不发奖，并提示「未看完广告」。
- 播放前若运行时存在 `wx.requirePrivacyAuthorize`，先走微信隐私授权；用户拒绝则不播广告、不发奖。
- 浏览器预览没有微信广告，用 `confirm` 模拟。Node 测试环境没有 `confirm` 时按「看完」处理，只为覆盖发奖逻辑，真机不会走这条分支。

这是相对 MVP 的行为收紧：旧版在微信广告失败时会退回 mock，且没有 `confirm` 时直接发奖。

## 6. 埋点

统一走 `track(event, props)`。若基础库有 `wx.reportEvent`，会把布尔转成 0/1 后上报。事件必须先在微信后台配置同名事件，否则上报失败只打日志，不影响对局。本地保留最近 80 条，便于预览时在控制台核对。

| 事件 | 时机 | 字段 |
| --- | --- | --- |
| `app_launch` | 启动 | `version` |
| `privacy_accept` | 首次同意 | `version` |
| `home_view` | 回到首页 | `level_index` |
| `level_start` | 进入一关 | `level_index`，`reason`（start / continue / next / restart / replay） |
| `bottle_select` | 选中或改选 | `level_index`，`bottle`，可选 `reason=reselect` |
| `pour_commit` | 倒水动画落定 | `level_index`，`from`，`to`，`color`，`amount`，`moves` |
| `pour_reject` | 非法目标 | `level_index`，`reason`（full / mismatch / rule） |
| `level_clear` | 过关 | `level_index`，`moves` |
| `level_stuck` | 无步可走 | `level_index`，`moves` |
| `ad_request` | 请求激励视频 | `placement` |
| `ad_result` | 广告结束 | `placement`，`rewarded` |
| `extra_bottle` | 空杯到账 | `level_index`，`used`，`cap` |
| `undo` | 撤销成功 | `level_index`，`free`，`moves` |
| `bgm_toggle` | 切换背景音乐 | `muted` |

## 7. 合规与隐私

游戏不申请昵称、头像、好友关系或定位。本地只存三件事：

| 键 | 内容 |
| --- | --- |
| `caidaoshui_progress` | 已解锁关卡下标 |
| `caidaoshui_privacy_v1` | 是否已同意当前隐私说明 |
| `caidaoshui_bgm_muted` | 背景音乐是否关闭 |

首次开始或继续前，主按钮文案是「同意并开始 / 同意并继续」。点击即记下同意并进入关卡。页脚持续展示「本机存档 · 微信激励广告」。完整说明文案在 `PRIVACY_SUMMARY`。

上线前在微信公众平台配置《用户隐私保护指引》，声明本地存储与激励视频。代码在播广告前调用 `wx.requirePrivacyAuthorize`（基础库提供该接口时）。不要在广告未完整观看时发放空杯或撤销。

内容是抽象颜色谜题，没有用户生成内容和社交榜。适合全年龄向休闲分类，仍以微信平台审核结论为准。

## 8. 平台约束

- 项目类型是小游戏，不是小程序。入口 `game.js`，配置 `game.json`，`deviceOrientation` 为 `portrait`。
- 逻辑分辨率 750×1334。画布缓冲用窗口尺寸乘像素比，绘制和真机触摸都经过 `Screen` 这一处换算。
- 运行时代码是 TypeScript 编译出的 CommonJS，微信环境用 `require` 加载 `js/`。不要在小游戏包里依赖 DOM。
- 音频使用 `wx.createInnerAudioContext`，`useWebAudioImplement: false`，以便和 `wx.setInnerAudioOption({ obeyMuteSwitch: false })` 共存。背景音乐在隐藏和音频中断结束后按用户静音偏好恢复。
- 主包目前远小于 4MB 限制。上传忽略 `src`、`tests`、`docs`、`node_modules`、`preview`。
- AppID：`wx50da0aafbce43359`。仅用于本项目配置，换号时改 `project.config.json` 并在后台同步隐私与广告位。

## 9. 明确不做

账号系统、云存档、排行榜、分享助力、关卡编辑器、皮肤商城、插屏或 Banner 广告。这些都不在当前版本。
