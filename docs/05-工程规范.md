# 工程规范

## 1. 日常流程

1. 从当前分支改 `src/`、`tests/` 或 `docs/`。
2. 玩法规则改动要同时改 `tests/rules.test.js` 或点击回归，不能只改表现。
3. 关卡改动只改 `src/data/levels.ts`，跑通 `npm test` 里的合法性与求解。
4. 提交前执行 `npm test`。微信里看的是 `js/`，所以本地预览或导入开发者工具前要 `npm run build`。
5. 不要提交 `node_modules/`、`js/`、`preview/`、`project.private.config.json`。开发者工具生成的私人配置留在本机。

广告位、AppID、隐私文案属于配置：

- AppID 写在 `project.config.json` 的 `appid`，当前为 `wx50da0aafbce43359`。
- 广告位只改 `src/services/placements.ts`。
- 隐私摘要改 `src/services/privacy.ts` 的 `PRIVACY_SUMMARY`，并同步公众平台的隐私指引。

## 2. 代码风格

- TypeScript 严格模式，并打开未使用变量、未使用参数、隐式返回检查。能用类型说清的地方不用 `any`。微信 API 集中声明在 `src/types/wx.d.ts`。
- 缩进 2 空格，UTF-8，LF。见 `.editorconfig`。
- 对玩家可见的字符串用中文完整句子。
- 注释解释意图和平台限制（例如为什么不用 WebAudio 实现、为什么晃动必须清相位），不重复代码字面意思。
- 文件名用小写中划线或单个单词，与现有目录一致。
- 新的纯逻辑放进 `src/core`，并且不引用 `wx`、画布和 `session.game`。需要读对局状态的代码留在 `src/app` 或 `src/render`。

## 3. 模块约定

- 一关的可变状态只有 `session.game`。渲染可以读它、改按钮列表，不要另建一套瓶子数据。
- 动画时间只用 `game.now`。
- 真机坐标只用 `clientToDesign` / `Screen.touchToLogic`。
- 存储键不要散落新字符串。进度和隐私用现有常量；新增键时写进需求文档的隐私表。
- 埋点只用 `track`。事件名用小写加下划线，字段值只用字符串、数字或布尔。
- 奖励只能写在广告 Promise 的成功分支里。

## 4. 构建

`npm run build` 做两件事：

1. `tsc`：`src/**/*.ts` → `js/**/*.js`，模块格式 CommonJS，目标 ES2018。这是微信运行的代码。
2. `esbuild`：把 `src/main.ts` 打成 `preview/game.bundle.js`，给 `index.html` 用。微信上传配置已忽略 `preview/`。

`game.js` 在运行时 `require('./js/main.js')`，再调用挂到 `GameGlobal` 上的 `GameMain.start`。

## 5. 音频与图片

运行时使用 `audio/*.mp3`、`images/home-hero.png` 和 `avatar_caise.png`。路径相对小游戏包根目录，不要写成 `http` 或以 `/` 开头。音效优先 mp3；源文件里的 wav 备份没有放进仓库，避免把约 3MB 的 `bgm.wav` 打进主包。

## 6. 审查时看什么

- 规则变化是否仍满足「同色或空瓶、一次倒完连续顶层、四层封顶」。
- 点击是否仍是瓶子优先于底栏。
- 广告失败是否没有发奖。
- 新存储字段是否写进隐私说明。
- `js/` 是否只是构建结果，而不是人工补丁。
